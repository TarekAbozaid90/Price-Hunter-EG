## Ревизия 2026-11-03 (ثالثة) — `npm start` للـ Render وأي Node-استضافة

**المشكلة:** فشل النشر على Render بالخطأ `npm error Missing script: "start"`.
المشروع لم يكن فيه سكربت `start` إطلاقًا (كان `dev` و`build` و`preview` و`test` فقط)،
وRender يشغّل `npm start` افتراضيًا، فالحاوية كانت تخرج فورًا.

**الحل:**

- سكربت `scripts/serve.js` — سيرفر ملفات ثابتة بدون أي اعتمادية خارجية: يخدم `dist`،
  يقرأ `PORT`، يستمع على `0.0.0.0`، يمنع الخروج من مجلد البناء، ويستخدم types MIME
  صحيحة + كاش للملفات المسمّاة بالهاش + fallback لصفحة واحدة (SPA).
- سكربت جديد `npm start` (و`npm serve` كاختصار) في `package.json`.
- الإعدادات المقترحة لـ Render: Build `npm ci --include=dev && npm run build`،
  Start `npm start`، Node `22`، Health Check `/`.
- `engines.node >= 20.19.0` موجود في `package.json`، وRender يحترمه ويختار Node المناسب.

**فحص:** البناء + التشغيل محليًا: `/` و`/data/catalog.json` و`/assets/*` يرجعون 200
بـ types صحيحة، والمسار غير الموجود يرجع `index.html`، ومحاولة الخروج من مجلد البناء
ترجع الصفحة الرئيسية بدون تسريب أي ملف.

### 2. Уведомления по Email и WhatsApp

- `collector/emailer.py` — отправка через SMTP (только стандартная библиотека).
  `EMAIL_HOST`, `EMAIL_PORT`, `EMAIL_USER`, `EMAIL_PASSWORD`, `EMAIL_TO`,
  `EMAIL_STARTTLS`; SMTPS на порту 465, `EMAIL_TO` принимает несколько адресов.
- `collector/whatsapp.py` — WhatsApp Business Cloud API (Graph API) через `urllib`.
  `WHATSAPP_TOKEN`, `WHATSAPP_PHONE_ID`, `WHATSAPP_TO`.
- `collector/runner.py` — доставка по нескольким каналам одновременно. У каждого
  канала своё состояние (`channels` в журнале), поэтому неоднозначная отправка
  блокирует только свой канал, а не все. Старые журналы без `channels` читаются
  как прежде (Telegram).
- Новые команды проверки связи: `test-email`, `test-whatsapp`.
- Интерфейс: кнопка **«Уведомления»** в шапке открывает окно с Email, WhatsApp и
  Telegram. Подписка на Email идёт через `mailto:`, на WhatsApp — через `wa.me`.
  Контакты каналов берутся из `config/monitor.json` → `alerts`
  (`email_address`, `whatsapp_number`, `telegram_bot`), значения по умолчанию
  пустые, поэтому кнопки объясняют, что заполнить.
- `collector/config.py` проверяет формат адреса, номера и имени бота.

### 3. Исправлен поиск

- **Причина:** вкладка «Находки» показывает только статусы `confirmed` и `possible`.
  В снимке данных все 40 наблюдений имеют статус `insufficient`, поэтому поиск по
  умолчанию всегда возвращал пустоту и выглядел как сломанный.
- **Исправление:** при введённом запросе поиск идёт по всем наблюдениям; фильтры
  магазина, категории, статуса и цены продолжают применяться к результату.
- Поиск идёт по названию, артикулу, бренду, модели, варианту, магазину и категории;
  регистр, `ё/е` и знаки препинания не влияют на результат; несколько слов
  трактуются как «и» (каждое слово должно совпасть).
- В поле поиска появилась кнопка очистки, над результатами — строка «Поиск по всем
  наблюдениям: найдено N», а пустой результат объясняет, где искать.
